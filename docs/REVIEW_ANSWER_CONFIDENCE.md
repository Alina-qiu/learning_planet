## 作答与排序

客户端要求每题提交前选择“不太确定 / 有点把握 / 很有把握”，分别保存为 1 / 2 / 3。作答把握不改变判题、金币、XP 或 1/3/7/30 天复测规则。答案判定后只读；旧记录未采集时显示“未记录”，不从正确率、OCR 或模型结果推算。

迁移 `202611050063_review_answer_confidence.sql` 增加题目的 `last_answer_confidence`、任务题目的 `answer_confidence` 与 `previous_answer_confidence`。每日新队列按以下顺序选择，仍最多十题：

1. 家庭时区的到期日期升序，即逾期天数较多的优先；同一天不比较时分秒。
2. 错误次数降序。
3. 上次作答把握升序，未记录的排在有记录的之后。
4. 题目 UUID 升序，确保并列项稳定。

生成时冻结顺序及上次把握，重复生成不重排已有任务。新答题更新本次及题目上次把握，答错也记录。编辑题目造成内容版本变化时清空当前把握；旧内容或旧阶段/排期的任务仍保留自己的答案与把握，但不能覆盖当前题目的把握。

## 事务与兼容

新五参数 `submit_review_answer` 的 `answer_confidence` 无默认值；旧四参数入口仍保留。旧客户端新作答记为未知，并清空题目上一次把握；旧客户端重放已判定答案只返回既有记录，不清空已有值。已判定答案不能补填或改选把握。两个入口都先取得账号/家庭访问锁，再进入任务与答案事务，沿用权限、有效时长、奖励唯一回执和软上限保护。

离线 `review_answer` 命令可增加整数 `answer_confidence`，旧命令省略仍兼容；其他命令不能附带该字段。它随原 UUID、答案及后继完成命令写入加密 SQLite，进入服务端请求指纹。重复命令的选择必须一致，丢失回执后重试原命令，不重复发奖。服务端判题、把握、排期及最后一题结算全部在同一事务中，最低时长不足等失败全部回滚。

客户端显示待同步答案的选择和发生冲突的本机选择；不在离线状态判题或入账。题目和任务项的新列随现有 CSV 导出，孩子永久删除级联清理，无新导出分区。

## 4 工作分解

### 4.1 工程和基础设施

- 安装 Flutter 稳定版、Android Studio、Xcode（iOS 打包必须使用 macOS）。
- 执行 `flutter create . --platforms=android,ios` 生成平台工程。
- 建立 development、staging、production 三套配置。
- GitHub Actions 执行 format、analyze、test 和构建检查。
- Supabase CLI 管理迁移；禁止在控制台手工修改生产结构。
- 崩溃和日志不得记录完整题目、图片 URL 或儿童身份信息。

### 4.2 账号与权限

- `users`、`families`、`family_members`、`children`。
- 家庭管理员、普通家长、孩子和系统服务四类权限。
- 所有业务表启用 RLS，并通过家庭成员关系授权。
- 家长 PIN 仅存强哈希；连续 5 次失败锁定 10 分钟。
- 删除账号前生成数据范围预览，并使用异步删除任务。

### 4.3 任务系统

- 模板和实例分离，实例一旦生成即保留当天规则快照。
- 支持 `scheduled → ready → in_progress ↔ paused → completed`。
- 完成接口使用 `idempotency_key`，重复调用只产生一条账本记录。
- 家长补签必须填写原因并写入 `audit_logs`。
- 通知默认开始前 10 分钟、开始时和截止前 15 分钟；超时不扣分。

### 4.4 每日自动错题复习

- 服务端以家庭时区每天 00:05 执行，应用启动时提供补偿检查。
- 筛选 `review_due_at < 次日 00:00` 且未掌握的错题。
- 按逾期时间、重复错误次数排序；默认最多 10 题。
- 使用 `(child_id, due_date, source_type)` 唯一约束防止重复。
- 生成 `task_instances` 后，将题目复制到 `task_review_items` 形成快照。
- 开始后新增错题不插入当天任务；超出题量顺延并显示积压。
- 全部题目作答后完成任务；金币与 XP 按实际结果事务化结算。

### 4.5 积分与奖励

- 钱包余额只通过账本推导和校验，不允许客户端直接写余额。
- 兑换申请事务：可用余额减少、冻结余额增加、生成申请。
- 拒绝/取消：冻结金额全额退回；履约：冻结金额正式消耗。
- 每日金币软上限 150；超出后 XP 正常，金币等待家长确认。
- 学期调价只影响新记录，不追溯历史账本。
- 家庭共享库存与每个孩子的周期/累计兑换限次；申请预留，拒绝/取消/过期释放，履约消耗，双设备竞争不得超卖。实现及验收口径见[奖励库存与兑换限次](REWARD_INVENTORY.md)。

### 4.6 错题、OCR 和 PDF

- 原图、处理图和 OCR 文本分开保存。
- OCR 原始结果和最终校对文本都保留，低置信字段必须确认。
- AI 只能提出知识点和错误原因建议，不能直接发奖或修改掌握状态。
- A4 默认纵向、边距至少 12 mm；答案页独立可选。
- PDF 在服务端确定性生成；生成任务可重试且不重复收费。

### 4.7 离线与同步

- Drift/SQLite 保存最近数据、未同步命令和版本号。
- 普通内容最后写入优先；钱包使用账本；任务完成使用幂等命令。
- 恢复网络后 30 秒内启动同步，失败指数退避。
- 界面展示已同步、同步中、离线和冲突四种状态。

## 8 风险与对策

| 风险 | 对策 |
|---|---|
| 自动复习任务重复生成 | 数据库唯一约束、幂等 RPC、定时重跑测试 |
| 家庭时区或设备改时 | 由服务端家庭时区判定日期，客户端时间仅展示 |
| 积分账本不一致 | 只追加账本、事务、余额定期重算和差异告警 |
| AI/OCR 出错 | 置信度、人工校对、规则复算、版本审计 |
| 个人开发范围失控 | 锁定 MVP，动画、AI 学习伙伴和教材库后置 |
| iOS 无 Mac 无法打包 | 尽早准备 Mac 或使用受控云构建，第四周前验证证书链 |

## 9 完成定义

MVP 完成不是“页面写完”，而是以下证据全部成立：两端同步可验证；自动复习任务生成幂等；离线打卡可恢复；钱包可由账本重算；兑换状态闭环；错题 PDF 可用；隐私和删除路径可操作；真实家庭连续使用两周。

# 角色成长与家长奖励

对应PRD 6.4积分经济、6.8静态成长及主动挑战/老师表扬/考试进步规则。孩子从首页“我的角色与成长”查看等级、连续记录、徽章、装扮与伙伴；家长在当前家庭PIN有效时进入“家长成长奖励”。

## 成长与展示

- 迁移055补齐[大厅角色与离线成长记录](OFFLINE_GROWTH.md)：大厅和成长页共用角色/徽章/伙伴预览，最近同步记录加密保存；断网显示记录时间及原日期，禁止修改装扮与进入家长奖励。恢复在线刷新后可继续更换，读取/修改和权限清理相互隔离，不提前结算离线XP。
- 迁移018从已结算任务的XP账本驱动连续记录，即使该任务奖励为0也能记录完成。每个孩子、每个应完成日期只有一条记录。
- 连续日期采用已完成任务的due_date，不采用设备日期。家长有原因的补签可补齐历史日期；普通离线任务确认同步后才显示成长。界面明确说明该口径，它表示完成任务日期的连续性，不是对真实学习行为的独立认证。
- 连续3天首次奖励30金币，7天首次奖励徽章与50XP，30天首次奖励装扮与150XP。每项里程碑终身只结算一次；重复完成、同天多任务、重新形成连续记录均不重复领奖。连续中断不扣除既有金币、XP或物品。
- 迁移020提供两个基础角色和两个免费伙伴。每5级解锁一项资产，等级上限50；连续7/30天也解锁对应物品。选择角色或装扮不消耗资产，不触发发奖。
- 角色、徽章、装扮、伙伴分别保存。更新一个位置不会覆盖其他位置。锁定资产显示条件，服务端再次验证资产归属与类型。普通孩子模式可更换已解锁物品；家庭隔离仍以child_is_visible/RLS为边界。
- 角色外观采用Flutter静态图标、颜色和边框组合，有文字与语义标签；没有战斗数值、开放聊天或学习地图。后续已补齐[任务完成的小怪兽反馈和声音/动画开关](TASK_COMPLETION_FEEDBACK.md)，效果不参与奖励结算。

## 今日主动挑战

家长填写名称及最低有效时长（0至120分钟），服务端以家庭当天创建一条真实任务，固定30金币、25XP。任务中心和首页带“挑战”标记，沿用开始、暂停、最低时长、完成及普通任务离线同步流程。创建不发奖，完成后通过原有事务账本结算。

同一孩子同一家庭日期最多一条挑战实例，数据库唯一索引和事务锁处理两个设备的并发创建。请求UUID可重放；同UUID更换孩子、名称或最低时长会失败。重复完成不重复结算。周期模板中的普通任务仍是普通任务，不自动被视作挑战。

## 表扬与考试

家长必须填写日期、事件名称和确认说明，操作需要有效会话PIN；未来日期不接受，不要求录入老师姓名、学校、考试原始分数等个人信息。

| 类型 | 规则 |
|---|---|
| 老师表扬 | 30至100金币、20至50XP；由家长确认，原始说明进入事件和审计记录。 |
| 考试 | 绝对分档与进步档各配置50至200金币、30至100XP；不用的档位都填0，至少启用一档。 |
| 考试取高 | 选金币较高的一整档；金币相同选XP较高的一档。不会相加，也不会把两个方案各自的最高金币/XP拼成第三档。原始两档及最终结果均保留。 |

金币通过现有learning_event账本类型结算，同样受每日150默认软上限约束，超额进入待家长确认；XP正常入账。事件记录中的奖励数额包括可能尚待确认的金币，页面明确说明。账本按实际入账显示余额。

事件UUID与标准化请求内容绑定；同UUID不同数据拒绝。同一孩子/类型/日期/名称还有业务唯一约束，防止换UUID再次提交相同事件。不同名称是否代表同一现实考试由家长保证，应用不能从两个任意名称判断它们是同一次考试。历史页展示最近50条记录；完整历史仍保存在数据库。

客户端先展示金额确认，再提交；网络结果不明确时保留原始内容与UUID，锁住编辑并提供“重试同一请求”。已成功结算后的本地同步失败不会被表述为奖励结算失败。页面关闭或进程结束不保存未确认表单，重新进入应先查看任务/事件记录；数据库幂等与业务唯一约束仍生效。

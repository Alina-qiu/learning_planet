# 已有数据的数据库升级演练

验证日期：2026-11-06。针对开发计划的历史数据升级门槛，在本机 PostgreSQL 15.19 中依次应用真实迁移，并在五个历史版本写入业务数据，再继续升级至迁移066。共68个迁移文件，14项检查通过；完整数据库回归另有387项通过。

本演练使用一次性数据库及 Auth/Storage 表结构夹具。业务写入经实际 RPC、家长 PIN 和数据库权限执行，私有答案及原始字段比较由测试管理连接读取。它验证数据库升级兼容性，不包含真实 Auth/Storage 服务、托管 Supabase、文件备份恢复或生产回滚。

## 历史版本与数据

| 写入时点 | 已应用文件数 | 升级前创建的状态 |
|---|---:|---|
| 008 task maintenance | 10 | 家庭、两个孩子、已完成任务、未开始任务及奖励账本 |
| 011 wrong question review | 13 | 数学和拼音错题、已冻结的复习题序和答案、只完成一题的复习及原作答命令 ID |
| 013 wallet redemptions | 15 | 家长调账、已审批未履约兑换、100金币冻结余额和审计记录 |
| 017 worksheet dispatch | 19 | a4-v1待生成试卷，冻结拼音/数学顺序、标准答案与打印配置 |
| 030 durable image uploads | 32 | 同步租约、未发送的开始/完成命令、原版本及前后继关系 |

升级后比较15类表的既有字段，完成34次历史行比较；其中包含不同快照对同一账本行的比较，不能理解为34条独立业务记录。允许新增字段，原字段值必须保留。

## 升级后验证

- 旧已完成任务以原回执和新回执再次提交，余额及原账本 ID 均不变。
- 升级前保存的离线开始/完成命令仍可提交；再次重放不重复发奖，新增任务仅产生两条奖励账本。
- 旧复习保留原答案、原奖励规则及手动完成方式；未采集的把握仍为空，重复作答回执不改题目。完成两题按旧规则结算10金币/10XP。
- 已审批兑换继续履约，释放原100金币冻结额；重复履约只有一条支出账本，并执行钱包对账。
- 旧待生成试卷领取时升级到a4-v2，题序、答案、配置、路径和过期时间保持原值。此处检查数据库快照，不生成PDF文件；文件闭环见[PDF集成](PDF_INTEGRATION.md)。
- 新调账明细接口能读取升级前的操作者、时间及原因；未验证PIN的新会话被拒绝。
- 升级后创建的新复习采用阶段奖励、孩子作答把握和最后一题自动完成，订正结算15金币/15XP。
- 无关账号读不到七类家庭业务表，不能获取同步快照或领取试卷。

## 运行与证据

使用项目要求的 Node.js 22或以上；先安装仓库锁定的依赖，再运行：

```text
npm ci
npm run test:db-upgrade
npm run test:db
```

Windows 当前工具链也可直接运行脚本：

```powershell
& 'C:/Users/qiuya/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe' scripts/test_database_upgrade.mjs
```

需从仓库根目录执行。工具自动分配本机端口，创建临时数据库，并在结束后关闭连接和数据库进程，不连接既有开发或云端数据库。

- 报告：`build/database_upgrade/results.json`，记录运行 ID、各迁移 SHA-256、历史写入时点、通过的检查和数据库关闭状态。

# 商城与经济历史分页

2026-11-05。对应 PRD 的奖励商城、兑换记录、金币/XP 账本和主要列表首屏目标。

## 已实现

首次打开读取钱包汇总和四类列表的首批数据，每类最多50条。商城、兑换历史、待确认金币和账本分别提供“继续查看”入口；只有进入可见区域的行才构建 Widget。历史记录不再一次全部下载，完整孩子导出仍包含全部记录，保持40类数据。

迁移056新增 `economy_page` 和四类查询索引。参数包括孩子、家庭、列表类型、上次页面末尾的 `created_at` / `id`、页大小和是否包含下架奖励。服务器允许1–100条，客户端固定50条；排序为时间降序、UUID降序，用末条游标读取下一页。服务器多取一条确定是否还有数据。相同时间戳和页间新增/删除不会因偏移变化造成已读记录重复或跳过游标之后的旧记录。

儿童商城仅取上架奖励，家长模式可查看下架奖励；该筛选沿用原家庭读取权限，不替代家长PIN校验。配置、审批、履约和调账继续使用原授权流程。待确认列表仅返回 `pending`；兑换记录保留所有状态。普通账本页面不再显示内部幂等键，完整导出保留原字段。

商城仍使用原库存、限次、家庭日期、XP等级、余额和有效期规则，读取前沿用原到期退款检查，因此商城读取可能处理过期申请。兑换历史、待确认金币和账本分页已在数据库只读事务内验证；不能将商城读取描述为完全无副作用。

## 数据范围与重试

- 响应绑定账号、孩子、家庭、列表类型和筛选条件；客户端核对每行归属、顺序、重复ID、最多50条和游标末行。错误结果不追加。
- 账号切换、仓库销毁、孩子删除、账号注销、成员撤销或家长模式改变后，旧响应失效。
- 翻页断网保留已有记录，可重试同一页；明确权限拒绝隐藏已显示的经济记录。
- 刷新和经济操作开始时使在途翻页失效；成功操作后重新读取钱包和首批列表。旧余额/库存下发出的翻页请求不能追加到新结果中。
- 商城翻页发现家庭日期改变时要求刷新，防止混用两天的限次结果。不新增金融离线快照或离线结算。

这是逐页读取，不是跨请求的事务快照。其他设备更新状态、价格或库存后，已展示的旧行可能需要刷新；提交申请仍由服务器再次校验价格版本、库存和余额。旧记录可以继续查看，首批数据不能代表历史总数。服务端总量统计、真实网络时延和设备渲染需单独测量，不能据此宣称首屏已达到1.5秒。

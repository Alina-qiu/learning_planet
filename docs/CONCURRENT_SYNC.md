# 多会话同步、账本与库存并发联调

更新：2026-11-06。对应PRD ACC-02/03/04、AC-02/04/05/08，以及开发计划中的同步/账本并发检查。本套件验证本机服务上的有界并发和请求重放，不用于宣称云端容量、手机性能或完整发布验收已经达标。

## 实际运行的组件

沿用固定的PostgreSQL15.19、PostgREST16.2、GoTrue2.196.0，应用迁移001–066共68份及70份官方Auth迁移。所有账号通过实际邮箱验证码流程建立，邮件仅投递到回环SMTP。四个不同家长加入同一家庭，每人拥有独立会话；另建一个未加入家庭的账号验证读取/调用隔离。没有直接插入业务表、伪造用户JWT或绕过PIN。

四个设备实例使用真实Supabase SDK、任务/奖励Repository及四个不同文件的Drift数据库。这里的“设备实例”指测试进程中的独立客户端，不是四台实体手机；文件队列验证不替代原生加密库和安全存储验收。

## 两个场景

1. 两个孩子各10个任务，每个任务25金币/20XP。四个客户端先读取相同初始版本，断网后各保存20条开始/完成命令，总计80条；关闭并重开文件数据库后逐项核对原始队列。四方并发同步，在真实服务成功提交完成操作后丢弃回执，继续用原请求恢复。发生版本冲突的命令须显式读取并采用服务器状态，不能假装全部提交成功。最终每个孩子10个任务完成、20条奖励账本、150金币/200XP与100待确认金币；核对源任务+资产唯一、钱包可由账本重算。再重放全部80个原始命令，账本ID、待确认ID和余额均不改变。未加入家庭的账号不能读取这些任务/账本或调用同步快照。
2. 使用另外两个孩子独立准备兑换余额，避免依赖第一个测试成功。四个会话争抢一份100金币的家庭共享库存，必须恰好一方成功，其他方明确报告库存/余额拒绝。成功申请冻结100金币；四方同时拒绝后再次重复拒绝，共8次退款调用，只出现一条退款账本，余额完整退回且冻结归零。失败竞争者不生成额外申请或扣款。

同步场景显式调用Repository同步方法，不测量“联网30秒内自动触发”。回执丢失仅在实际HTTP200且业务结果为`applied`时注入；普通权限错误或版本冲突不能被计作已提交后丢失。并发中的胜出者和冲突数量允许变化，验收依赖最终任务、金额、唯一性及原记录ID不变。

## 运行与报告

准备方式与[真实Auth集成](AUTH_INTEGRATION.md)相同，使用Node24及Flutter3.47.4，设置`POSTGREST_BIN`、`GOTRUE_BIN`和必要时的`FLUTTER_BIN`后运行：

```sh
npm run test:concurrency
```

入口为`scripts/test_concurrent_integration.mjs`；实际客户端场景为`scripts/fixtures/concurrent_client_test.dart`。CI的PostgREST16.2任务已接入该命令，尚未远程执行。

权威汇总为[本次并发结果](../build/concurrency_integration/results.json)。驱动在开始时将报告置为未通过，两个场景通过、客户端运行ID一致且实际流量符合要求后才写入完成；失败会写入失败状态，不能误用之前的成功报告。日志和报告不保存验证码、JWT、邮箱或题目正文。临时数据库和服务由原有夹具在成功/失败路径关闭；本地队列文件保留在该次专用临时目录用于诊断，不修改正常App数据。

首轮测试发现夹具错误读取了不存在的家庭日期字段，已改用服务端时间和家庭时区；兑换场景也改为独立准备孩子/余额。失败日志`tmp/concurrency-integration-first.log`保留，没有因此修改生产规则或放宽金额、唯一性和权限断言。

最终两项通过（Flutter测试阶段12秒）：10次Auth、286次PostgREST请求、5封本机邮件。任务场景实际丢失4次已提交回执，2轮同步后显式解决2个任务的冲突；全部金额及ID检查通过。任务场景4980ms包括准备任务、文件重开、同步、重放与校验，不能解释为纯同步耗时或吞吐量。日志为`tmp/concurrency-integration-final.log`，269个Dart文件格式检查通过；第二次成功运行是补齐运行ID/失败报告及独立文件路径检查后的复测，不另累计为更多业务场景。

最终完整静态分析无问题（38.8秒），见`tmp/concurrency-integration-analyze-final.log`。临时服务已关闭；两种既有APK摘要再次核对，仍对应[构建记录](ANDROID_BUILD.md)中的当前产物。

业务Dart、SQL和原生代码未改，不重建APK，不重复计入之前的778项Flutter、387组数据库和90.94%核心覆盖率。原安装包与两端验收限制见[构建记录](ANDROID_BUILD.md)。

# 家庭时区设置

更新：2026-11-05。补齐 PRD TSK-01“时区变化时按家庭时区生成，不回填重复实例”的可操作入口。默认仍为 Asia/Shanghai，手机时区改变不会自动改变家庭设置。

## 设置与生效范围

家庭与孩子 → 家庭时区。家庭管理员在有效家长 PIN 授权内，按中文城市名或 IANA 时区名称搜索选择，并显式保存。页面展示服务器计算的家庭日期、当前及待保存时区，说明任务、报告和每日金币上限使用家庭日期。

时区变化影响后续生成。已有任务的绝对开始/截止时刻、复习到期时刻、题目快照、计划规则、打卡命令和账本保留；显示时可按新时区换算。只生成当前家庭日期，不补建跳过的中间日期。切回已生成日期时沿用同一实例，不重复奖励。该行为由现有任务唯一键、复习每日唯一键和奖励回执继续保证。

## 服务端

迁移 `202611050064_family_timezone.sql`：

- `families.timezone_version` 单调递增；触发器校验 PostgreSQL 的有效时区名，并递增已有家长通知设置的版本，不改变通知开关或安静时段。
- `family_time_settings` 及 `set_family_timezone` 均要求管理员及当前会话 PIN。撤销客户端对 timezone 列的直接写权限；客户端不能伪造版本。
- 修改使用预期版本比较。相同预期版本及目标时区的回执重试返回原结果，只有一次版本变动和审计；期间发生其他修改（包括改走后再改回）会拒绝旧请求，要求刷新核对。
- 保存账号、家庭、操作者、前后时区和版本审计。生成函数先取得家庭读取锁，修改先取得家庭写锁，真实双连接验证生成会等待时区事务提交。

功能不依赖手机时钟来选择家庭日期，不新增离线时区写操作。旧任务及离线同步租约继续有效。

## 客户端与提醒

修改前后均清除家庭、计划和提醒缓存，并使正在进行的旧读取失效。家庭列表写入 SQLite 时同事务复核变更代次，避免写到一半的旧响应恢复旧时区。操作保持原有待同步任务命令，失败也不清空打卡。

本机先暂停原生提醒、移除旧家长投递策略，阻止修改期间的定时刷新重新排入旧提醒。已开启的后台家长提醒在时区保存后，重新取得通知设置并注册新策略；恢复失败时保持关闭并提示核对。任务同步确认另一个设备的新时区后，重新读取家庭设置，更新界面和提醒协调器。

保存结果不明时保留原选择和预期版本，可重试原设置，或联网刷新后核对当前值。账号切换、PIN 授权变化、家庭撤权或隐私清理会拒绝迟到结果。关闭页面后不排入新的离线修改；再次打开读取服务器当前设置。

其他离线设备无法即时获知家庭时区变化，已有本地提醒须在恢复网络并刷新后更新。此限制在页面明确说明，未宣称具备即时跨设备撤销能力。

# AI学习周报与逐条反馈

对应PRD 6.9、7.1的V1.2学习周报及7.2输出契约。迁移036、Flutter入口和共享AI网关已有本地实现；未部署云端、配置真实模型或进行家庭试用。原有日/周/月统计和规则建议仍可独立使用，AI不会创建任务、结算金币或更改掌握状态。

## 使用流程

家长验证PIN → 学习报告 → “周报 · 近7天” → 选定日期 → “AI解读这份周报”。展开查看将发送的汇总数据，明确同意后才生成。进入页面、查看统计、查看依据或提交反馈都不会自动调用模型。

结果显示1至3条事实摘要、一条行动建议、模型/提示版本与低置信提醒。每条都有“查看依据”和“这条建议不准确”。依据页显示该条引用的服务端数据快照及统计口径，不将刷新后的数字替换到旧结论中。AI文本仍可能错误；引用有效只证明引用了已知数据范围，不证明自然语言推理或数值表述正确，需家长核对。

响应丢失时核对原请求；重启后恢复原UUID及加密保存的输入。重新生成必须先明确结束旧请求、重新查看数据并同意，计入新额度。一个孩子同时保留一个本机AI请求，分类、相似题和其他日期的周报不会互相套用。PIN到期遮蔽周报及嵌套依据页；登录变化、本机隐私清理和孩子删除阻止迟到响应回写。

## 最小输入与依据

`weekly_report_ai_context`复用受家长授权保护的`learning_report`，只返回固定结构`weekly-facts-v1`。供应商只收到snapshot内的日期及数字，不收到child_id、家庭ID、姓名、年级、时区名称、任务标题、题目、答案、图片、备注或原始活动明细。

| 依据编号 | 数据与边界 |
|---|---|
| tasks | 所选7天按到期日分组的已生成任务数量、当前完成数量和已保存计时；排除批准请假，计时不等于该周实际总用时 |
| daily | 相同口径的连续7天计数与时长，保留零样本日期；与tasks汇总一致 |
| activities | 所选日期实际完成任务的数量，按完成时间计入，可包含此前到期任务 |
| reviews | 所选日期已判定复测作答及正确次数，不提供原始答案；零样本不计算正确率 |
| due_now | 生成时as_of_date当日到期且未掌握的题数；排除归档/删除中题目，不声称是历史周末状态 |
| coins | 所选日期按入账时间统计的收入、已履约消费和其他调减；冻结、退款不算产消 |

发送前客户端保存所见输入；领取请求时服务端重新计算同一孩子、同一日期的统计并精确比较。如果同步、补签或日期跨日导致数据变化，在扣额度前拒绝，用户须结束旧请求并刷新。成功领取后把权威输入放入该请求的私有`result.evidence`，运行中的公开回执隐藏它；完成时由数据库附加到结果，模型不能自行提供或篡改依据。

## 输出、费用与生命周期

- 使用同一个`ai-analysis`Edge入口、OpenAI Responses适配器和家庭AI设置；没有额外密钥或Cron。家庭开关仍默认关闭，所有AI用途共用月次数及预算预留。
- `weekly-report-v1`采用严格JSON Schema、固定依据枚举、每条1至3个引用、非空文本及长度限制。客户端只展示普通文字，不执行模型内容或打开外部链接。适配器与SQL均拒绝无效引用、重复引用及部分判断性词语/链接；这不能代替真实模型安全与质量评测。
- API固定地址、`store:false`、20秒超时、64KiB响应上限、最多2500输出token；拒答/安全标记抑制正常建议和raw_output。服务端再次核对模型/提示版本、形状和长度。
- 沿用统一JSON字段：model_version、prompt_version、confidence、raw_output、structured_output、safety_flags；数据库额外附加evidence。低于0.8提示重点核对，自报置信度不是校准后的正确率。
- 本地冻结输入保存在既有加密`ai-request:<child>`中，随结束、相关本机清理、孩子/账号删除清除。服务端依据与模型正文共用同一个result，无额外长期快照表；保留期1/7/30天、关闭AI、取消、题目清理及删除都会清除它们，并撤销相关临时导出副本。
- 运行中请求超过保留期也显示expired并清除依据，旧UUID不会再次派发；迟到模型结果无法恢复已清除内容。第三方模型可能另保留安全审查记录，`store:false`不等于供应商零保留。
- 逐条反馈只有固定`inaccurate`类型和条目编号，不收集自由文字。相同请求/条目幂等；不触发模型或费用。反馈关联版本，随请求/孩子删除级联清除。

孩子导出现为34个CSV：原`ai_analysis`内包含未过期的周报和依据，新增`ai_report_feedback`包括条目、反馈类型、时间及模型/提示版本。运行中的依据不导出，过期/清理后不再导出正文。已下载副本由用户自行管理。

## 验证与部署

按序部署001–036迁移及更新后的`ai-analysis`，确认已有AI保留Cron运行。先选定支持当前结构化输出的模型，再校准分类1500、相似题/周报2500最大输出token所需的保守预算；示例100分预留不是供应商报价。云端配置目前保持关闭。

新增11项Flutter检查和7组真实PostgreSQL检查，覆盖入口日期、显式同意、原请求恢复、跨用途/家庭隔离、PIN、逐条反馈、实际Supabase SDK、隐私清理、精确统计来源、两连接并发、篡改/过期/关闭及真实删除工作流。全量268项Flutter、205组PostgreSQL通过，静态分析无问题；适配器和真实Deno入口使用本机HTTP模拟，4个Edge入口类型检查通过；已检查中文正文/依据页和360px双倍字号。

上线仍需真实模型的引用一致性、零样本/补签/时区样例、安全表达、费用与保留政策评测，以及两端弱网、权限、可访问性和连续家庭验收。本轮不增加自动周报通知、专用PDF或离线统计报告。

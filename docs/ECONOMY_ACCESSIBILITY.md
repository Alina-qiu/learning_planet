# 奖励页的大字号与窄窗口适配

2026-11-12 对照 PRD 第9章的系统字号、平板可用性要求，检查奖励商城、兑换记录和金币账本。

## 问题与修复

旧页面把钱包摘要和本机待确认请求固定在列表上方。在640×320逻辑像素、两倍字号下，钱包区导致底部溢出84像素，挤掉奖励列表；待确认请求还可能进入底部系统区域。横屏或平板侧边安全区域也没有被正文避开。

现在三个标签保持可切换，钱包摘要、待确认请求和当前列表协调滚动。待确认请求不再使用固定240像素的独立滚动区；加载中、读取失败和权限错误的提示也可以滚动，并保留可用的请求核对入口。正文避开左右和底部系统区域。

兑换确认、幂等请求、家长权限及金额规则沿用原有实现。浏览页面不会自动重试资金操作。

## 验证范围

- 新增5项回归：360×800竖屏、640×320横屏、1024×768平板窗口，全部使用两倍系统字号和模拟安全区域；实际执行兑换确认，切换记录/账本，检查按钮可点击且不进入系统区域。
- 横屏待确认请求分别在奖励数据可用和读取失败时执行“停止未执行请求”，验证只取消原请求、没有兑换入账。
- 相关41项测试通过；全量823项Flutter测试通过，核心行覆盖率90.75%，静态分析无问题。最终构建对应的检查以草稿PR的CI为准。
- 使用中文字体生成并检查三张布局截图，分别显示横屏申请入口、横屏待确认操作和平板奖励列表。

实现：`lib/features/economy/presentation/economy_screen.dart`、`economy_pending_command.dart`；回归：`test/economy_layout_test.dart`。本机复现、回归及截图日志保留在忽略的`tmp/economy-layout-*`中。

这些是生产组件的窗口模拟检查，不能替代华为鸿蒙4.2/iPhone真机、读屏或平板系统分屏验证。用户当前没有可连接的测试手机，真机项目继续列为待验收。

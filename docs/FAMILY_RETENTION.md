# 家庭次日与第7日回访

对应 PRD 第11节，迁移043。以家庭为单位观察首次创建任务后的应用前台活跃，不以任务完成、后台同步、提醒送达或模型请求代替回访。家长日/周/月报告展示本家庭的观察结果；全局留存率由仅限服务端调用的汇总函数提供。

## 起点与日历

- 起点是家庭首次创建的非 `automatic_wrong_review` 任务实例，包含普通任务和长期计划。数据库触发器记录事务中的服务端时间，忽略客户端填写的创建时间；回滚不留下起点。自动生成的复习占位任务不启动队列。
- 首次任务发生时冻结家庭时区及当地日期。以后切换时区、增加孩子、修改或删除任务，都不重置这个家庭起点。
- 第1日、第7日分别是起点日期加1、加7的完整当地日，不是连续24/168小时，也不是“7天内任意一天”。午夜通过时区转换，包含夏令时的23/25小时日。
- 已存在的家庭标记为 `legacy`。迁移只能找到仍保留的最早任务，不能证明此前没有删除过任务，因此历史家庭不进入可信留存分母；没有剩余任务的历史家庭也不冒充新家庭。

## 活跃采集与离线

`ReminderCoordinator`在当前选中家庭的学习界面及从它打开的页面处于前台时采样，启动、恢复和每30秒检查一次。后台、销毁后的页面、未登录、未配置后端不采集；每个家庭日只需一个样本。该记录说明应用处于前台，不证明持续专注、孩子身份或实际操作者。

样本只有家庭UUID和UTC时间，先写入现有按账号隔离的加密Drift缓存 `family-activity:<family>`，再调用 `record_family_activity`。客户端保存最近7天待传样本、最多9个去重日期；单次请求最多16个样本，10秒超时，失败间隔30–300秒重试。上传失败、回包丢失及重启均保留原时间，不把旧回访挪到上传当天。

服务端验证活跃账号、家庭成员及载荷，接受最近168小时且不晚于服务端当前时间的样本。过期或未来样本明确确认丢弃，客户端随后用服务端时间校准；进程内使用单调计时避免系统时间跳动。离线冷启动仍依赖设备UTC，错误时钟、超过7天的断网、卸载及本地删除可能造成缺失，因此“未记录到回访”不等于证明从未使用。

服务端按冻结时区计算日期，只保存起点日至第7日的日期，每家庭最多8行。同日重复、两个成员或两台设备的重复上传由主键去重，没有原始时间序列、设备标识、题目正文、任务或孩子ID。家庭时区设置变化会触发重新核对冻结时区。第7日的补传期结束后，客户端停止该家庭的后续采集。

## 状态与汇总分母

报告中的“家庭回访”属于家庭初次使用队列，与当前孩子报告所选日期范围无关。

| 状态 | 含义 |
|---|---|
| 尚未创建任务 | 尚无起点 |
| 历史记录不足 | 旧家庭，原始首任务或历史活跃不能可靠还原 |
| 起点缺少活跃采集 | 起点当天及之前没有受理过前台采样，不计入可靠分母 |
| 尚未到观察日 | 对应当地日期尚未开始 |
| 观察及离线补传中 | 已到观察日，还未收到回访，补传期尚未结束 |
| 已记录回访 | 对应日期存在活跃样本，成熟前仍不进入最终比率分母 |
| 未记录到回访 | 完整观察日及补传期已结束，没有受理到回访样本 |

每个观察日结束后额外保留168小时补传期。`family_retention_summary(cohort_from, cohort_to)`只允许 `service_role` 调用，按首任务日期筛选最多367个日期，分别返回第1/7日的总家庭数、成熟分母、已回访分子、尚未成熟及缺失家庭数。分母为0时比率是null，不显示0%。历史与未采集家庭单列；这是有采集覆盖的存量家庭队列统计，家庭删除后退出统计，并非不可变的全平台历史增长账本。

原始表与内部快照函数禁止客户端直接读取。家长报告沿用会话PIN和孩子可见性校验，Flutter另核对家庭ID、版本、日期与状态；PIN失效后隐藏旧报告。统计不影响任务状态、金币/XP、奖励或AI输入。

## 导出与清理

孩子的家长授权导出新增 `family_retention.csv`、`family_activity_days.csv`，共享家庭统计不标识具体孩子或家长；后续迁移044加入配置计时、048加入复习预约后，ZIP当前共39个CSV。原有AI来源、采纳、题目/周报反馈及家长消息回执也已补齐客户端白名单，数据库回归核对实际服务端清单中的每个类别均可由Flutter打包。

删除孩子时清除本机所有待传家庭活跃缓存，并用隐私代次阻止迟到回包写回；账号注销清除本账号缓存。服务端已形成的共享家庭起点和首周日期保留给仍在家庭中的成员，孩子删除不重置整个家庭的首任务。家庭实际删除时两张表级联清除；账号注销后的旧会话不能继续上传。此行为与个人任务、错题及图片的删除范围不同，导出说明明确标记为家庭共享数据。

## 验证与部署

按顺序部署迁移001–043，不需要新增Cron、外部埋点平台或供应商凭证。旧客户端忽略新增报告字段，新客户端容忍旧报告缺少回访字段；未部署043时采集RPC失败保留有界队列，不阻断学习，但无法生成留存统计。

- `scripts/test_family_retention_cases.mjs`：6组真实临时PostgreSQL检查，覆盖首次任务、自动复习排除、起点冻结、重复/无效/过期上传、第1/7日、补传成熟期、历史/未采集排除、服务端汇总、PIN/RLS、当前39类导出、夏令时与家庭级联删除。
- `test/family_retention_test.dart`：12项检查，覆盖真实SQLite关闭重开、丢失回包、断网有界队列、时钟校准、冻结时区、前台生命周期、账号/删除屏障、真实Supabase SDK模拟传输、ZIP类别、非法统计与360px/两倍文字/PIN失效。

最新全量结果见[测试说明](TESTING.md)。本轮未部署真实Supabase，真机跨端、长期离线、真实家庭采集覆盖率与时钟偏差验收仍待完成。

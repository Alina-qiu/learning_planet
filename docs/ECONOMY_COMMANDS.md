# 兑换申请与家长调账的请求恢复

2026-11-05：对应PRD奖励兑换、账本可靠性与幂等要求。此前请求编号及价格/调账内容只存在页面内存，关闭页面后无法继续核对同一请求。本次把生产入口的兑换申请和家长调账接入加密持久请求及服务端回执，不在本机修改金币、冻结额或XP。

## 使用行为

- 用户确认后先把固定UUID、孩子/家庭、原命令和显示内容写入加密SQLite，写入成功才发送。每个账号/孩子同时最多一项未确认的兑换申请或调账；不同孩子独立。金额、奖励版本及调账原因在重试时保持不变。
- 离开页面、应用关闭或网络回复丢失后，重新打开商城仍显示原请求。页面加载、恢复前台均不自动提交；商城读取失败、奖励已下架或库存耗尽时，顶部恢复区仍可独立核对。
- “核对结果”只查询原回执，不冻结或调账。“重试原请求”再次确认后使用原UUID；已受理则返回原结果。“停止未执行请求”只停止尚未执行的请求，迟到提交不能执行；已受理的操作不会撤回。
- 已受理的兑换需要取消时，仍在兑换记录里按原状态机取消和退款；已完成调账不静默反向修改账本。用户确认已知结果后才清除本机待办并允许新申请。
- 超过500金币的调账仍须第二次确认；调账内容、核对、重试及确认清除都需要当前家庭PIN。PIN失效时隐藏金额/原因和恢复按钮，仅提示重新验证。更换账号、授权版本变化、清理或注销后，不采纳旧结果，也不在新账号下提交旧弹窗。
- 请求区在手机大字号下可滚动，页签可横向滚动；停止/重试弹窗支持滚动。服务端仍决定余额、库存、次数、等级及有效期；本机待办不等于已冻结金币。

## 服务与存储

按顺序部署迁移001–051。本次新增`202611050051_durable_economy_commands.sql`，未部署远程环境。

`resolve_economy_command(child,request_id,command,operation)`支持`redeem`/`adjust`命令及`submit`/`inspect`/`cancel`操作。账号、家庭成员与孩子权限始终检查，调账另检查会话PIN。请求锁串行提交/停止；家庭共享锁与成员移除串行，孩子共享锁保护业务写入及回执的同一事务。原`request_reward`、`adjust_wallet`继续负责库存/限次、金额、大额确认、钱包锁和追加账本规则。

私有`economy_command_receipts`只存请求哈希、归属和有限结果，不重复保存奖励规则、金额或调账原因。相同请求绑定原孩子和完整命令；核对不会触发过期清理或业务提交。取消可处理原始字段无效、提交已被拒绝的请求；取消屏障和业务成功结果都是持久回执。孩子或账号删除时回执级联清理，旧请求不能重建已删除孩子。已有业务账本和审计的保留/导出规则保持一致，39类导出不增加内部回执。

本机使用`economy-command:<child_id>`缓存键，存于当前schema5的加密数据库，无新SQLite结构。新增孩子归属识别，使孩子删除、账号注销和家庭权限撤销同时清理待办；响应写回也核对账号、PIN版本、隐私版本及原请求是否仍存在。等待中的请求不会被后台自动重放。旧版客户端使用原接口，不具有新页面跨重启核对体验；应先部署服务端再升级客户端。

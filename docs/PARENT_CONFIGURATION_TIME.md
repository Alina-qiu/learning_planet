# 家长配置用时

对应PRD第11节“每周任务与规则编辑总时长”，迁移044。家长日/周/月报告展示本报告期间、整个家庭已同步的编辑用时；周报仍使用所选日期截至当天的7日范围。计时不依赖保存次数，取消的编辑也计入，未采集的历史不补算。

## 覆盖入口

| 分类 | 编辑范围 |
|---|---|
| task | 新建/修改普通任务、重复日程与长期计划（含计划内奖励规则）；首次任务引导；计划请假日期与原因 |
| rules | 初始积分与奖励规则；商城奖励的价格、库存、限次及履约规则；每日金币软上限；任务提醒与静默时段 |

浏览任务列表、学习计时、审批/履约、手工调账、修改孩子档案、PIN、AI开关及家长个人通知偏好不属于本项任务/规则编辑指标。直接开关某个任务的操作没有独立编辑窗口，不把其网络请求耗时当作编辑时长。新建任务的首次日期加载在编辑页之外，保存请求也在编辑页退出后执行。

## 前台会话

`ConfigurationTimeScope`包住编辑页面/弹窗，首个显示帧后开始记录，只有该家庭的有效家长PIN仍在授权期内才计时。每15秒采样，退出/取消时收尾；正常返回路由时即停止，不等待退场动画或保存HTTP请求。

计时使用单调时钟，包含阅读和思考时间。指针、滚轮、键盘和Form输入变化只刷新无操作期限，不记录输入内容，也不为每个按键创建一个事件。连续2分钟没有操作后暂停；下一次输入重新开始，暂停间隔不补算。任务日期选择器沿用所在编辑会话。进入后台、系统弹窗导致应用不活跃、PIN失效时暂停，恢复后只记录新时间。

单个保存区间最多30秒。当前会话以创建时已知的服务器UTC或设备UTC为起点，之后由单调时钟推进，不随系统改时增减已计时长。服务端拒绝未来区间和起点早于168小时的区间；错误时钟不会被修正成“今天多编辑了几分钟”。异常退出可能丢失尚未落盘的末段。

## 离线与重放

事件先进入按账号加密的Drift缓存 `configuration-time-v1`，字段只有事件UUID、孩子/家庭UUID、task/rules、开始和结束时间。每账号最多1000条、最长7天，超过容量时移除最旧样本；不保存字段值、任务名称、题目、键盘代码或设备标识。

每批最多50条，10秒上传超时，失败30–300秒后重试。前台协调器每30秒继续发送积压，编辑期间也可触发上传。回包丢失后复用原UUID和时间；同一UUID改载荷被拒绝，两个设备并发重复提交只保存一次。回执必须完整匹配本批UUID，不能清掉发送期间新写入的样本。较早回包校准服务器时间时仍保留未确认的新样本，由服务器最终验证其时间。

每次写入及回包处理核对账号、隐私代次和组件生命周期。孩子删除清空本机配置计时队列，账号注销清空本账号队列；旧会话不能恢复已清理的缓存。服务端对已撤销成员、已删除孩子或错误家庭范围的区间确认丢弃，避免一个旧孩子的记录阻塞其他孩子的待传样本。载荷结构或UUID复用冲突则拒绝整批。写入每账号每24小时最多10000个新区间。

## 报告口径

服务端按照报告家庭时区，把区间裁剪到报告日期范围及最近90天保留范围。跨午夜区间分别计入对应日期，夏令时按真实UTC间隔计时，钟面回拨不改变实际经过的时长。

同一账号在本家庭多个孩子、窗口或设备上的重叠区间取并集，然后把不同家长的用时相加。例如同一家长的两个20秒区间重叠10秒，合计30秒；另一位家长同期编辑20秒，家庭合计50秒。返回原始区间样本数和有记录的家长人数，界面不暴露身份或原始时间序列。

没有样本时显示“暂无配置计时记录”，不会声称维护成本为0。超出90天的查询显示只覆盖仍保留部分。指标只反映新客户端已采集并同步的区间；长时间离线、旧版本、错误设备时钟、本地清理和队列超限都会造成缺失。采集是客户端行为报告，不用于身份判定、权限、金币/XP、扣分或奖励。

学习报告继续要求当前会话家长PIN，客户端核对家庭ID、版本、数量和时长边界；PIN失效后隐藏旧报告。AI周报的事实白名单没有扩大，不把这些时间区间发送给模型。

## 权限、导出与保留

`parent_configuration_intervals`禁止客户端直接读取。采集RPC要求活跃登录账号与孩子/家庭成员权限，UI的PIN限制不被用于授予服务端业务权限。报告仅返回家庭汇总。

孩子授权导出新增 `parent_configuration_time.csv`，只包含当前家长为该孩子产生的区间，不含其他家长数据、owner_id或载荷哈希。ZIP当前共39类CSV；实际服务端清单与Flutter白名单的契约测试同步检查新增类别。

孩子删除、账号注销受理以及家庭成员移除时立即清理对应服务端区间；家庭最终删除另有外键级联保障。因此历史汇总是当前仍保留资料的统计，不是不可变的审计账本。原有临时导出和本地隐私清理流程继续适用。

部署迁移001–044后，按[配置计时清理脚本](../supabase/operations/enable_configuration_metrics.sql)在目标环境启用每日清理任务，仅服务角色可执行，删除90天之前的区间。即使清理任务延迟，报告和新导出也只读取保留范围内的数据。本轮只提供脚本，没有在云端执行。
